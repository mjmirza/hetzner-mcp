## 2026-07-12 - URL-Encoded Path Traversal Bypass
**Vulnerability:** URL-encoded characters representing directory traversal (e.g., `%2e%2e`, `%2E%2E`) or platform-specific directory separators (e.g., `\\`, `%5c`, `%5C`) bypass literal string checks like `path.includes("..")`, but are resolved as directory traversals when passed to standard URL-parsing APIs like `new URL()`. This allows attackers or LLM clients to traverse out of the restricted API scope/base URL.
**Learning:** Checking relative paths only with a raw string check is insufficient when the target URL constructor decodes or normalizes the string prior to building the full URL. If input validation checks only raw characters, an attacker can use percent-encoded dots or backslashes to bypass the check, which the subsequent URL resolver then decodes and processes, leading to path traversal.
**Prevention:** Always decode user input via `decodeURIComponent` (or an equivalent URL-decoding function) and normalize it *before* running security validation checks such as directory traversal (`..`), backslashes (`\\`), or control characters checks.
