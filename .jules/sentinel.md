## 2026-06-07 - Path Traversal and SSRF via Percent Encoding and Backslash Bypass in WHATWG URL Parsing
**Vulnerability:** The application was vulnerable to path traversal and Server-Side Request Forgery (SSRF) because it validated relative API paths before URL normalization/resolution. An attacker could bypass the `raw.includes("..")` check by using percent-encoded dots (e.g. `%2e%2e` / `%2e%2e/` / `%2e%2e%2f`) or backslashes `\` / `%5c`, which Node's WHATWG `URL` parsing implementation automatically normalizes to directory traversals (`../`).
**Learning:** In standard Node.js WHATWG `URL` resolution, backslashes `\` are normalized to `/` and percent-encoded dots are decoded and resolved during parsing. Simple substring matching like `raw.includes("..")` is insufficient if validation is done on the un-normalized/undecoded raw path.
**Prevention:** Always decode URI paths using `decodeURIComponent` (catching any malformed URI errors) and explicitly check both the raw and decoded paths for path traversal markers (`..`, `\`) and control characters before passing them to URL constructors or using them in file path resolution.
