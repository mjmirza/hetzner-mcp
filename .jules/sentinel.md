## 2026-06-07 - Node WHATWG URL & Path Validation Vulnerability
**Vulnerability:** Under Node's WHATWG URL implementation, backslashes (`\`) are normalized to forward slashes (`/`), and percent-encoded characters (like `%2e%2e` representing `..` or `%5c` representing `\`) are decoded and parsed. If path validation is performed only on the raw input string without decoding percent-encoded sequences or checking for backslashes, malicious actors can bypass simple string-based path traversal blocklists. This could lead to server-side request forgery (SSRF) or path traversal.
**Learning:** Checking for path traversal (`..`) only in the raw query parameter string is insufficient when the string is ultimately appended to a base URL to form a WHATWG URL object. Node's WHATWG URL implementation will parse the string, resolve percent-encoded components like `%2e%2e`, normalize backslashes (`\`), and potentially allow access to unauthorized endpoints.
**Prevention:** Always decode paths using `decodeURIComponent` first, catch any potential malformed URI errors, and explicitly check both the raw and the decoded forms of the path for path traversal sequences (`..`), backslash characters (`\`), control characters, and newline/carriage-return sequences before using them in URL construction or HTTP client fetches.
